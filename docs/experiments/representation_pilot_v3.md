# 单树与条件三树：10代预实验协议

本轮回答两个问题：修复繁殖后能否保持实际探索，以及条件三树是否比联合单树更适合控制FACO。两种表示同时使用相同繁殖修复。旧的50代实验暂停，不把旧fitness续接到新个体；本预实验结束后不自动继续50代或打开正式测试集。

## 共同的求解与评价设置

| 项目 | 设置 | 依据与目的 |
|---|---|---|
| 问题 | 连续欧氏TSP500 | 本轮用户指定范围；距离和搜索采用FP64 exact后端 |
| GP seed | 1103、2207、3313 | 两种表示分别独立运行这3个seed |
| 种群和代数 | 128个体，10个完整评价代 | 保留现有GPU整种群并行容量，先检查退化和表示，再决定后续实验 |
| 每代训练 | 16实例×1个ACO seed×1000迭代 | 共用原单规模实验冻结的前10面板；各代实例会变化 |
| 蚂蚁数 | 128 | FACO2022论文公式 `64×ceil(sqrt(n)/16)`，n=500 |
| 其他FACO参数 | beta=1，保留率0.5，primary=16，backup=64，LS候选=20，p_best=0.1，epoch source概率0.01 | 继承已经核对的2022 FACO设置，详情见[参数依据](../design/implementation_v2.md) |
| 个体fitness | 16实例终局参考gap的算术平均，越低越好 | 返回tour按既有坐标距离与`math.fsum`外部计分，避免LS增量累计舍入打破同分；参考值和标签路径不进入求解器 |
| 开发监控 | g5、g10：原16个monitor实例×seed17×H1000 | 只观察冠军，不逐代验证全部种群 |
| 结束比较 | 每次进化的g10冠军，32开发实例×seeds17/29/41×H5000 | 使用既有H校准的development记录[96:128)，不访问正式val/test |
| GPU | 所有服务器当前空闲RTX A5000 | `gpu-free`发现，UUID核查和共享租约，6次进化可分卡 |
| 预算 | 真实tour evaluation次数 | 无ACO或进化时间上限；SSH和空闲worker管理超时不属于算法预算 |

一代实际训练FE为 `128×16×128×1000=262,144,000`；每次10代为2,621,440,000，六次为15,728,640,000。重复行为不会复用fitness或跳过真实ACO评价。每次进化的监控为4,096,000 FE，结束开发比较为61,440,000 FE，分别记账。

## 四个对照

1. FACO2022的既有连续距离适配：MNE8，8个CPU线程，24条原生初始路线。
2. GPU FACO：MNE8，从完整tour均匀选择起点，不重启。
3. 固定MNE16、region0、不重启：对应旧实验中常胜的`mne_level`叶子。
4. GPU FACO MNE16：从完整tour均匀选择起点，不重启。

第3和第4项用于分开“增加MNE”与“限制起始区域”的作用。复用记录必须匹配实例、ACO seed、H、距离和求解设置；缺项补跑。旧原生和GPU baseline不因更换GP表示而重跑。训练面板和监控baseline齐备后启动进化；结束开发比较的baseline可同时补跑。

## 表示与动作接口

完整动作有32种，编号 `16×restart + 4×region + level`。restart为0/1，region为0..3，level为0..3，对应MNE2/4/8/16。`joint_single`用一棵树为32个完整动作评分，取合法最大分，差距不超过1e-6视为并列，选最小编号。

`conditional_three`有三棵角色树，作为一个个体共享同一个最终fitness：

| 树 | 比较的候选 | 可读特征 |
|---|---|---|
| restart | 保持或重启，共2项 | progress、stagnation、return_rate、ls_work、restart、ref_gap、ref_diff |
| region | 已选restart下的4个区域 | 除mne_level以外的11个特征 |
| mne | 已选restart和region下的4档MNE | 全部12个特征 |

父分支下至少存在一个合法完整动作时，该分支才合法。三次评分都使用同一个动作前状态；全部选完后才执行一次控制事务。GPU在一个warp内完成三个阶段，Python不参与ACO迭代。三树轨迹记录2/4/4个阶段分数、阶段mask和选择，不伪造32个联合分数。

## 共同繁殖修复

| 参数 | 设置 |
|---|---|
| 初始化 | ramped half-and-half，目标高度2/3/4分层；full/grow交替 |
| grow的有限生成 | 随机保留一条到目标高度的分支，其余分支从深度2起按grow概率终止 |
| 树大小 | 每棵高度≤5，整个个体总节点≤63；三树按节点之和约束 |
| 精英 | 4个；全部在下一代新面板重新评价 |
| 父代 | tournament=4，同fitness随机选择，不优先短树 |
| 算子 | 80%交叉、15%变异、5%复制，互斥选择 |
| 交叉/变异节点 | 90%非终端、10%终端；根节点可选；所需类别不存在时从现有节点选 |
| 变异子树 | 通常高度0..2；单叶树增长变异高度1..3 |
| 第二父代 | 优先不同64情境行为向量；最多25次，找不到改做变异 |
| 无效交叉/变异 | 结构未变或越界均重试；分别记录尝试、结构变化、行为变化和接受数 |
| 同代结构 | 128个完整IR直接比较后均不同，不使用哈希 |
| 同代行为 | 任一64情境完整动作向量最多2个个体 |
| 每个位置的上限 | 最多25次繁殖尝试，其后最多128次随机移民；仍不满足时明确失败 |

三树交叉选同一角色作子树交叉，另两角色整树交换，从而同时重组规则组合；变异均匀选择一个角色。复制和精英也不能越过同代唯一IR与行为容量。高度按边数定义，单叶高度0、层数1，仍是合法进化结果。没有强制使用反馈，也不保证最终树一定复杂。

精确IR比较包含表示、角色顺序和每棵树的完整操作码、操作数及FP32常数位模式。普通个体编号不参与结构判重。行为向量相等只说明在这64个情境中动作相同，不证明全局语义等价。

## 固定的64个行为情境

原首训练面板前4个实例，使用其第1个ACO seed；分别以固定MNE2/4/8/16、region0、不重启运行H1000。在完成0、31、255、999次迭代、准备下一次动作前采样：4×4×4=64。底层1起算的decision_iterations为1、32、256、1000。

采样强制计算全部12×32特征，不能沿用生产环境的“未使用区域特征不计算”优化而留下零值。仅保存特征、合法mask、采样位置和控制参数，不保存蚂蚁工作区或完整求解快照。一次性真实ACO开销2,048,000 FE单独记账，工程检查与六个正式run共享同一文件。

实际检查发现，旧AQ的CUDA `rsqrtf`与CPU `1/sqrtf`偶尔有约1.2e-7的分数差，足以改变恰在1e-6边界的并列选择。保留既有数值语义，正式PC直接使用训练的同一个CUDA评分器。CPU协调器把初始化/繁殖作为短任务交给空闲GPU，候选的64个情境在warp上评分；这不进行ACO搜索，不增加ACO FE。记录实际繁殖耗时，目标为整代额外开销≤5%。CPU独立核对分支、mask和并列选择；AQ数值按既有误差契约核对，旧单树CUDA行为必须保持一致。

## 论文依据与本项目取舍

[Zhang、Mei、Zhang，2018，多树GP](https://fangfang-zhang.github.io/files/2018-AI-Multitree.pdf)把routing与sequencing作为一个多树个体共同评价，并提出交叉一个角色、交换其他角色的规则组合方法。80/15/5算子比例和90/10节点选择也见于该实验。

[2021 TCYB特征选择研究](https://fangfang-zhang.github.io/files/2021-TCYB-FeatureSelection.pdf)同样使用80/15/5和90/10；其种群、深度、代数服务于调度仿真，不直接移植为本项目最优参数。这里保留128种群、tournament4和63节点预算，以隔离繁殖修复与表示差异，并控制GPU代价。

[2026 ECJ行为禁忌表研究，作者稿标为2025](https://fangfang-zhang.github.io/files/2025-tabu-ECJ.pdf)使用固定决策情境的phenotypic characterisation及有限重试来处理重复行为。本项目取25次重试这一有文献实验依据的起点，但64情境、容量2、移民回退和严格唯一IR是本项目协议，不能称为逐项复现。论文里的哈希存储不采用。

[2019表示研究](https://fangfang-zhang.github.io/files/2019-EvoCOP-NewRepresentation.pdf)说明，所有候选共同加上的量可能不改变排序。这里因此报告反馈替换为1后，在64个情境中实际改变动作的次数，而不以“树出现了反馈终端”作为反馈有效的证据。

## 运行、恢复与证据

入口 `scripts/run_representation_pilot.py --launch`；正式入口先要求`results/v3/representation_verification.json`通过。六个run路径以表示和GP seed共同命名，旧Program/旧实验结果仍可读取。检查点同时保存种群、fitness、随机状态、PC和每代记录，恢复按普通任务编号读取已完成分片，不计算内容摘要、不重复计入FE。

向实验目录写`pause.json`后，协调器停止新提交，已提交GPU分片落盘并释放设备；以`--resume --launch`恢复。只启动本项目登记的进程，设备租约和主机/PID/start_ticks用于避免操作其他用户任务。

原始记录在`artifacts/v3/`，精简检查和图在`results/v3/`，可读结果见[预实验报告](../reports/单树与三树预实验.md)。需要报告6条训练/开发曲线、各seed结果、冠军表达式、实际输入输出示例、有效繁殖率、唯一PC数、树大小、动作分布和反馈干预。3 seed不能保证统计显著，也不能只凭更深的树判断修复成功。
