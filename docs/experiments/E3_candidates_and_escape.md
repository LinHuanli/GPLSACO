# E3：候选质量与有限出口

状态：预注册草案。候选工具链、Hard/Escape语义和全新增边测试通过后才能冻结。四条件为alpha-Hard、alpha-Escape、POPMUSIC-Hard、POPMUSIC-Escape，每条件各比较Static与独立重训的GP-Full。

## 1. 候选准备

锁定本地LKH 3.0.13副本及研究使用声明，构建输出在GPLSACO内。先验证其候选导出路径、节点编号、先验分数和原问题距离；不要猜测内部函数是稳定API。alpha/POPMUSIC决定成员，LS另外按真实距离排序。原始先验排序与距离排序同时保存并校验。

四条件同一初始tour，基础边实际数量、访问槽位、内存预算匹配；记录无向图实际度数、总边数和例外容量，不只写“k相同”。POPMUSIC产生的tour不能额外作为更优初始化。主方法默认图条件须在正式测试前选定，E3不能用于事后挑最有利主结果。

## 2. Hard 的执行契约

`E0=冻结候选图∪共同初始tour边`。每次重定位在抽样前计算真正新增边：移出节点后的补边和两个插入连接；所有新边在E0才合法。2-opt两条新边都在E0。恒等操作和相邻节点做专门去重判断，不把被删又加的相同边误判为新边。

构造和LS始终满足tour边⊆E0；候选与声明回退枚举无合法移动时终止本次构造/检查，不无限重试，不悄悄出图。档案和reference只由合法tour生成。

## 3. Escape 的开发定义与待冻结量

使用相同基础候选，加先验后续排名和少量均匀采样形成有界备用。开发候选为每次机会以固定概率1/16替换四分之一枚举槽位；只替换，保持每节点每次槽位总数相同。数值和随机流经过开发成本检查后统一冻结，不由GP学习。

必须在实现前把“扰动相关LS例外”编码为明确规则：为本次非恒等重定位的受影响端点保存有界例外邻接条目；LS只允许E0或该次有效例外中的新增边，例外不跨批无限累积。明确端点/边登记时机、容量、去重、溢出处理和失效；候选变化触发pending重新激活。只有这份规则通过逐边测试，才能称为可复现Escape；目前此部分仍是需实现校准的工作项。

图约束、转移枚举行和LS视图三者分离。Hard与Escape主机制比较都准备相同备用资料以隔离访问限制；补充端到端结果另给Hard省去备用准备的实际时间，不能只提供承担无用成本的Hard。

## 4. 统计与解释

两先验×两限制×两控制器完整矩阵；每个GP条件相同训练数据、grammar、资源但独立训练。配对报告Hard/Escape gap差、GP对Static差、工作量、访问槽位、图外边计数和资源。最优tour覆盖率只在离线计算，长度标签不能生成边覆盖率。

coverage=1仅说明标注最优tour在图中，不保证可达；coverage<1不排除其他等长最优tour。出口有收益或无收益均报告；若不同约束导致计算预算不匹配，先修协议再解释探索机制。
