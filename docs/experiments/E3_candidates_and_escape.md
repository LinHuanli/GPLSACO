# E3：候选质量与有限出口

状态：候选工具链、完整Hard/Escape及匹配v2真实开发面板已通过工程验收；正式四条件训练/验证和统计协议仍需冻结并执行。四条件为alpha-Hard、alpha-Escape、POPMUSIC-Hard、POPMUSIC-Escape，每条件各比较Static与独立重训的GP-Full。最新执行契约见[Escape v1](../planning/18_e3_escape_spec_v1.md)，证据见[完整验收](../reports/2026-09-09_escape_engine.md)。

## 1. 候选准备

锁定本地LKH 3.0.13副本及研究使用声明，构建输出在GPLSACO内。先验证其候选导出路径、节点编号、先验分数和原问题距离；不要猜测内部函数是稳定API。alpha/POPMUSIC决定成员，LS另外按真实距离排序。原始先验排序与距离排序同时保存并校验。

四条件同一初始tour，基础边实际数量、访问槽位、内存预算匹配；记录无向图实际度数、总边数和例外容量，不只写“k相同”。POPMUSIC产生的tour不能额外作为更优初始化。主方法默认图条件须在正式测试前选定，E3不能用于事后挑最有利主结果。

候选导出已完成[开发验收](../reports/2026-09-08_lkh_candidates.md)：真实原生成员、Pi/Alpha/转换成本与两种顺序均归档。相同上限80在alpha中得到每节点80成员，POPMUSIC仅2–16。此发现要求先冻结实际图/访问槽位匹配，不能直接将两个原生输出作为等大小图进行E3主比较。先验采用明确的整数近似，LS仍使用原坐标FP64距离；未将POPMUSIC tour导入共同初始化。

## 2. Hard 的执行契约

`E0=冻结候选图∪共同初始tour边`。每次重定位在抽样前计算真正新增边：移出节点后的补边和两个插入连接；所有新边在E0才合法。2-opt两条新边都在E0。恒等操作和相邻节点做专门去重判断，不把被删又加的相同边误判为新边。

构造和LS始终满足tour边⊆E0；候选与声明回退枚举无合法移动时终止本次构造/检查，不无限重试，不悄悄出图。档案和reference只由合法tour生成。

2026-09-08，CSR图、逐边移动谓词、CPU受限LS/选择及CUDA同内核诊断已通过 [操作核验](../reports/2026-09-08_hard_operations.md)。穷举期望由完整移动前后tour边集产生；真实GPU选择覆盖全部五分支。拒绝的LS候选消耗其已进入的评价槽位，另记图拒绝数。当前普通Engine仍为无约束主底座，E3集成须进一步验证共同初始tour/E0、准备超时保留解的图可行性、候选导出与费用；操作通过不代表E3完整方法已实现。

## 3. Escape 的执行定义

2026-09-09完整Hard次数入口已通过[接入验收](../reports/2026-09-09_hard_engine.md)。历史匹配v1中备用实际成员数alpha为64、POPMUSIC为16。随后[匹配v2验收](../reports/2026-09-09_graph_slot_matching.md)在不改变E0或共同初解的前提下，匹配了32实例全部24,000节点的主/LS/备用实际数量；当前规则见[planning/15](../planning/15_e3_graph_integration.md)。本批两先验均有16个均匀备用、0个匹配后的原生尾部，不能再宣称实际使用了48个原生尾部。匹配v2的完整Hard/Escape工程运行已完成，正式四条件训练仍待执行。

使用相同基础候选，加先验后续排名和少量均匀采样形成有界备用。开发候选为每次机会以固定概率1/16替换四分之一枚举槽位；只替换，保持每节点每次槽位总数相同。数值和随机流经过开发成本检查后统一冻结，不由GP学习。

完整规则已在首次结果前登记并实现：显式替换槽位引起的非恒等重定位登记移动前五个端点，固定当前LS锚点；每蚂蚁每批64条无向例外边，全部新增边先原子预检、接受移动时整组提交，溢出整组拒绝且不永久继承。LS仅替换原有效槽位并按真实距离重排，参考足迹随parent/epoch/global/档案来源传递，旧视图失效重新进入pending。边界和随机取整详见Escape v1；CPU完整边差集、CUDA逐移动重放、容量边界及三类sanitizer均通过。

匹配v2的真实面板已完成34次调用/81,920 FE/1,088条返回tour及8组状态复用重放。记录了实际例外活动，但本开发预算下最终返回incumbent均仍在E0内；这不是收益或无收益的正式检验。独立GP训练、Static选择及配对统计尚未实施。

图约束、转移枚举行和LS视图三者分离。Hard与Escape主机制比较都准备相同备用资料以隔离访问限制；补充端到端结果另给Hard省去备用准备的实际时间，不能只提供承担无用成本的Hard。

## 4. 统计与解释

两先验×两限制×两控制器完整矩阵；每个GP条件相同训练数据、grammar、资源但独立训练。配对报告Hard/Escape gap差、GP对Static差、工作量、访问槽位、图外边计数和资源。最优tour覆盖率只在离线计算，长度标签不能生成边覆盖率。

coverage=1仅说明标注最优tour在图中，不保证可达；coverage<1不排除其他等长最优tour。出口有收益或无收益均报告；若不同约束导致计算预算不匹配，先修协议再解释探索机制。
