# E3：候选先验与有限出口

四个条件为 ALPHA-Hard、ALPHA-Escape、POPMUSIC-Hard、POPMUSIC-Escape。每条件分别选择 Static，并独立训练五个 GP-Full；各组使用与 v2 主实验相同的数值后端、论文蚂蚁数、训练预算和 5000 迭代验证/测试。

## 固定机制

两个先验共享初始 tour，匹配实际图边预算、逐节点访问槽位和备用容量；不能只声称候选宽度相同。POPMUSIC 产生的 tour 不作为额外更优初解。候选原生排序保留，LS 按真实目标距离排序。

Hard 的 `E0 = 候选图 ∪ 共同初始 tour 边`。重定位和 2-opt 所有真正新增边必须属于 E0，检查的是完整结构变化，不能把被删又加的相同边误判为新边。

Escape 保留已经实现的有限出口规则：机会概率 1/16、替换四分之一的原有效枚举槽位、每蚂蚁每批 64 条无向例外边，整组检查和提交，容量不足整组拒绝。例外不作为永久候选继承；参考足迹跟随来源，失效旧视图重新进入检查队列。详细算法见 [Escape 机制](../archive/v1/planning/18_e3_escape_spec_v1.md)。

候选导出、图匹配、Hard/Escape、外部可行性评分与训练接口均已合入主分支。v1 四组 Static 选择曾完成，但使用 32 蚂蚁，结果在 [实验总览](../reports/实验说明与结果.md) 中标为历史；v1 四条件 GP 训练未完成，不能续接进 v2 fitness。

v2 图目录采用普通实例编号和显式参数，候选与图仅在首次注册时读取。正式条件重训前，需要使目录覆盖全部共享训练面板、开发监控和验证成员，并重新完成每条件 Static 选择。当前自动主队列先完成数值/预算/两类 FACO 对照；E3 仍属于后续完整实验范围。
