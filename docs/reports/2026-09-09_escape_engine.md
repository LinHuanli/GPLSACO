# Escape完整Engine与匹配v2面板验收

Escape已接入共同CUDA构造、LS、parent/epoch/global、档案及重启路径，并开放次数型Python入口。该版本通过工程验收；E3四条件的独立GP训练、Static选择、正式配对检验和迁移仍未完成。主工作树十个E1训练及完整基线调优使用其原冻结源码和二进制继续运行。

实现契约在首次Escape结果前写入[Escape v1协议](../planning/18_e3_escape_spec_v1.md)。完整机器记录见[检查汇总](escape_engine_checks.json)与[真实面板审计](escape_engine_panel_results.json)。本次通过`gpu-free`发现空闲设备，再在每个任务前核对UUID、进程、显存和利用率；使用cuda05的两张RTX PRO 5000 Blackwell，driver 610.43.02，分别保存实际设备与资源记录。

## 已实现的边界

构造以固定1/16概率从备用表替换已有有效主槽位的期望1/4；少于4个有效槽位也采用明确的无偏随机取整。右侧哨兵不会变成额外候选。替代成员使用真实距离和已有信息素查询规则，独立Philox域不占用普通ACO随机流。

重定位全部3条、2-opt全部2条真正新增边经过整组预检，只有已选择并接受的移动才提交例外。每蚂蚁每批64条、无向去重、整组容量不足拒绝；未选择候选不写缓存，父tour不携带永久白名单。CPU以完整移动前后tour边差集作为期望，另在GPU直接构造容量61/62/63/64等边界，避免依赖搜索偶然填满缓存。

已接受的替换扰动只登记移动前五个端点作为当前LS锚点；这些节点的LS行替换原槽位并重新按FP64真实距离和节点ID排序。LS不追加第二遍候选扫描，也不把后续重激活节点扩张成新许可锚点。旧参考LS视图足迹随实际选中的tour、epoch、global和档案来源传递；例外失效时重新激活相应节点。完整图测试专门覆盖“没有图外tour边，仍须保留LS视图足迹”的情形。

Hard/Escape预留相同设备工作容量。最终版本让Hard跳过不会读取的Escape缓冲清零；清理前后34次真实调用的路线、成本、控制状态、FE、工作量、例外计数及预留容量全部一致。历史二进制和收据保存在`artifacts/escape-engine/native-v1`及`matched-panel-v1`，没有覆盖。

## 真实32×32面板

复用原32个开发实例和LKH先验，采用匹配v2的全部24,000节点；不重新选择数据或先验，不读取标签。两先验当前均为16个均匀备用、0个匹配后的原生尾部，不能写成使用了48个原生尾部。

34次实际原生调用覆盖两规模×两先验×Hard/Escape，包含0 FE共同初解、128 FE GP、64 FE Static以及128 FE GP的Engine EndToEnd重放。共81,920 search-tour FE、1,088条返回tour、384,000条Hard返回边及8组重复调用通过独立审计；坐标从原开发文件重读，图从冻结先验重建，最大独立成本误差为`3.552713678800501e-14`。

Escape合计554,525次构造机会、34,729次门控、46,979个主替换槽、8,534次替换扰动、57,000个LS替换槽、25,594次例外边登记及849次旧视图重激活。本面板未触发64边容量拒绝；该边界由上述设备构造测试覆盖。所有最终返回incumbent仍在各自E0中，不能用内部发生了例外登记来声称最终解获益。

500节点面板两模式均预留89,020,544设备字节，其中例外工作区52,940,672字节；1000节点分别为176,876,544和105,340,672字节。完整CLI实际14.51秒、最高CPU RSS927,232 KiB；34次调用内部墙钟之和5.797秒。独立审计实际32.67秒、最高RSS770,824 KiB。原LKH准备与匹配费用沿用旧收据，Engine EndToEnd没有重跑LKH，不能被称为包含全部外部准备的端到端时间。
