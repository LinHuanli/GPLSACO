## 正式规模与停止标准

四个条件为 alpha-Hard、alpha-Escape、POPMUSIC-Hard、POPMUSIC-Escape。每条件五个独立 GP-Full，seed 为 1103、2207、3313、4409、5519；每次完整 128 个体×50 代，6,400 次个体适应度评价，500/1K 两规模各一面板，共 12,800 次原生调用及 1,677,721,600 search-tour FE。20 次训练总计 33,554,432,000 FE，完整最终验证另计。

每条件另做完整 160 配置 Static 搜索与固定前十名验证，共 1,320 调用、173,015,040 FE；四条件共 692,060,160 FE。求解面板固定 16 实例×2 seed，32 colonies×32 ants，主预算 4,096 FE/colony。训练和 ACO 均无算法墙钟上限；Future 查询超时只等待原 Future。实际耗时保留作资源统计。

## 执行与审计

`research_e3.py` 校验冻结源码、图目录、全部主 split 成员、代面板、条件、seed 与实际设备，使用已有完整 GP/配置搜索事务。新增包装器先保存不可变原始返回，再查询 GPU；未知或外来进程观察使当前收据保留等待排查，不能因此重新评价。基础设施耗尽仍保留失败位置。

GP 审计逐条读取路线后释放，独立重算坐标身份、图输入、fitness 与整数资源；按原 seed 重放全部 DEAP、代面板、完整候选验证和最终导出。Static 审计独立展开完整参数族、搜索顺序、固定验证与选择，并核对独立原始返回。完整审计要求实际 CLI 终态资源收据；活动 checkpoint 只允许前缀报告。

`launch_e3_queue.py` 按 [固定设备计划v2](../../provenance/e3_launch_v2.json) 顺序启动独立 CLI，记录实际进程及退出码。最后空闲查询新增 cuda00 的 PRO 5000 与 cuda24 的 PRO 6000；v2 仅把两个尚未提交的 seed 5519 从原顺序队列移到新设备，原21设备计划仍保留。23 个设备分组拟同时运行19个GP和四个Static，另一个GP使用对应Static释放后的原UUID；新增型号须先通过真实兼容检查。后续 GP 不读取 Static 得分或策略。队列拒绝覆盖已有提交记录，恢复不能静默迁移或盲目重启。

## 真实开发验收

PRO 5000 上使用完整 2,296 实例图目录内的开发成员，保持正式 16×2 和 32×32 批形状，以 8×3、256 FE 验收新执行通路。GP 完成 48 次训练、五候选共 10 次验证，475,136 FE、1,856 路线；Static 完成四配置搜索及前二候选验证，共 20 调用、163,840 FE、640 路线。两阶段均无求解失败。

GP 第五次求解暂停前的七条准备/求解收据，以及 Static 的五条收据，在真实新建 worker 后保持文件与内容摘要不变；两阶段各经历三个 worker。独立 CPU 审计重放通过全部演化、选择和费用。整个 GPU CLI 74.76 秒，退出码 0；这是工程通路证据，不计入正式适应度或研究结论。

29 项针对性 Python 测试通过，覆盖正式规模组装、完整 GP/Static 恢复、面板不符时禁止提交、观察失败不重算和非法原生返回保留；Ruff 通过。未改动主树活动 E1/基线的核心源码与二进制，也未改变已封存的 18 项图准备源码。E3 原生仍为 `fdd64ce88f8e58b144c95cc97805fe213fc96bffeae7674d51be981aa4d701bd`。
