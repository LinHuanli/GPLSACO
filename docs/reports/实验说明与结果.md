**当前三 seed × 50 代实验集中在[三次进化实验](三次进化实验.md)**，包括配置、运行状态、曲线、FACO 对比和真实个体输入输出。本页保留背景、参数依据以及已有复现与性能证据；本轮不再启动旧的五 seed 接续任务。

本报告回答三件事：**我们在研究什么；每项实验怎样设置、为什么这样设置；现在实际得到了什么结果。** 当前版本为 v2，更新于 2026-09-09。日常状态见[当前进度](progress.md)，执行细节见[v2 协议](../experiments/protocol_v2.md)。

目前已经完成原始 FACO 的 180 次复现，并完成新 GPU 实现与训练管理的改造。数值精度、训练迭代数和完整配对 baseline 按预先登记的规则依次完成，具体状态见第 12 节。**目前没有正式测试结论，GP 是否优于 FACO 需要完整训练、最终选择和正式测试支持。**

## 1. 我们究竟要让 GP 学什么

FACO 是求解旅行商问题的蚁群算法：每只蚂蚁从参考路线出发，构造与参考路线部分不同的新路线，再用局部搜索改善它。本项目的 GPU 底座采用节点重定位构造和 checklist 2-opt。

GP（遗传编程）学习一棵小计算树。它不生成整条路线，而是在每轮 ACO 开始时为可行动作评分，控制三个决定：

| 决定 | 可选值 | 含义 |
|---|---|---|
| 是否重启 | 保持、重启 | 是否切换到档案中的另一条合法参考路线并重置信息素 |
| 从哪里扰动 | 4 个区域，各最多 16 节点 | 选择构造的起点；后续修改不限于这个区域 |
| 扰动多大 | MNE 为 2、4、8、16 | FACO 新边计数的停止阈值，不等同于改动节点数或最终保留的新边数 |

三项组合最多有 32 个动作。没有合法替代参考路线时，重启动作不可选。GP 使用求解状态、动作描述和历史反馈；NoFeedback 删除反馈终端后独立重新训练。

一个 GP 个体的评价流程是：固定实例和随机种子 → 运行规定次数的 ACO → 输出路线 → 外部评分器计算 gap → 按实例、再按规模等权汇总。最优值、参考 tour 和标签路径不会输入 GPU 求解器。

## 2. 为什么需要两个 FACO baseline

| 名称 | 实现与设置 | 回答的问题 |
|---|---|---|
| 原始 FACO 2022 | 作者的前缀构造、剩余路径复制、多初解与原生 LS；按论文设蚂蚁数 | 我们相对原始论文方法表现怎样？ |
| GPU FACO 无 GP | 与 GP 相同的节点重定位、初始化、LS、数值后端；固定 MNE=8、整条路线均匀选起点、不重启 | 学习控制本身带来多少提升？ |
| Static | 固定区域、MNE、重启规则，从完整配置族选择 | GP 是否优于调过参数的固定策略？ |
| Rule | 人工停滞/冷却规则，从完整配置族选择 | GP 是否优于人工反馈控制？ |
| NoFeedback | 删除反馈特征，按相同预算重新进化 | 求解历史反馈是否有用？ |

**Static 的“区域 3”仍然只在一个选定节点集合中取起点，不能冒充整条路线均匀起点的 GPU FACO。** 两者已使用不同的执行入口和方法名称。

原始 2022 FACO 与 GPU 底座的构造和初始化不同；GPU 版本不会被写成原始算法逐步等价的复现。GP 相对 GPU 无 GP 的差值用于解释控制收益，原始 FACO 则提供外部算法参照。

## 3. ACO 参数：来自哪里，哪些是自己的选择

以下论文参数对应 [2022 原始 FACO 论文 §5.6 的主性能比较](https://arxiv.org/html/2203.02228#S5.SS6)。原文中的大规模 TSP Art 组另有设置，本项目没有混用。

| 参数 | 当前值 | 选择依据与含义 |
|---|---|---|
| 每个 ACO 种群蚂蚁数 | `64 × ceil(sqrt(n)/16)` | 论文 §5.6，约 `4√n` 向上取到 64 的倍数 |
| 验证、正式测试迭代数 | 5000 | 同一论文实验组 |
| 训练迭代数 H | 开发集决定，冻结状态见第 12 节 | 从 100、250、500、1000、2500、5000 中按质量保留和排序稳定性选择 |
| 距离启发式 β | 1 | 论文表 1 |
| 信息素保留率 ρ | 0.5 | 论文 §5.6；表示保留比例 |
| 主候选 / 备用候选 | 16 / 64 | 论文表 1 |
| LS 候选宽度 | 20 | 2022 作者源码 `progargs.h` |
| 信息素边界 p_best | 0.1 | 同一作者源码 |
| 最好解作为来源的概率 | 0.01 | 同一作者源码；有重启时使用当前 epoch 的最好解 |
| 无 GP 对照 MNE | 8 | 论文 §5.6 |
| 每只蚂蚁 LS 移动检查上限 | 100000 | 本项目工程设置，所有同底座方法一致；不是论文设定 |
| GPU 初始化 | 节点 0 最近邻 + checklist 2-opt | 沿用底座；初始化 LS 检查上限也是 100000 |
| 档案容量 / 质量带 | 4 / 2% | 控制层预设，没有做超参数搜索 |
| GPU 一次并发独立求解数 | 32 colonies | 主训练面板为 16 实例 × 2 个求解 seed；这是批处理形状 |

源码默认的 `lround` 与论文要求的 `ceil` 不同。新入口显式按论文公式设置，不能再依赖源码默认值。TSP100、500、1000、10000 分别对应 **64、128、128、448** 只蚂蚁。

“32 个独立求解”“32 个可选动作”“128 只蚂蚁”是三个不同的数量。此前旧实验使用了 32 只蚂蚁，不能与本版混用 fitness。

本项目仍保留节点重定位底座的初始化和 LS 工作限制，并另跑作者原始 FACO。参数对齐不能消除这些算法差异，报告中会分别呈现。

| 面板随机 seed | 73001 | 在评价前登记完整 50 代面板，方法与进化重复间共享 |

运算空间包括加、减、乘、最小、最大、绝对值和 AQ 保护运算；树程序沿用有界 FP32 语义。这里的 GP 表达式运算与“ACO 距离搜索采用 exact 还是 FP32”是两个独立设置。

先前 8 个体 × 3 代的小运行只验证过工程流程，不能证明 128 × 50 最优或已经收敛。后续报告会显示固定开发监控面板上的学习曲线，再讨论是否仍有继续训练的空间。

## 5. evaluation 次数怎样换算

1 FE 指一只蚂蚁完成一次构造和局部搜索，返回一条完整路线。LS 内部尝试的移动、初始化和最终评分成本另记。设训练迭代数为 H：

| 层次 | TSP500 / TSP1000 的 FE |
|---|---:|
| 1 个实例 × 1 个求解 seed | `128 × H` |
| 一次 32-colony GPU 调用 | `4096 × H` |
| 一个 GP 个体，两个规模合计 | `8192 × H` |
| 一代，128 个体 | `1,048,576 × H` |
| 一次进化，50 代 | `52,428,800 × H` |

例如 H=500 时，一次进化训练约 262.14 亿 FE；H=5000 时约 2621.44 亿 FE。最终候选验证、每 5 代监控、baseline 和测试另计，不能说上述数字是全部实验成本。

50 代按完整评价次数结束，内层 ACO 按蚂蚁路线次数结束，**均不设算法墙钟上限**。运行时间只作为效率指标；暂停和恢复不会把已完成评价重新算入预算。

指标统一为 `gap(%) = 100 × (返回路线长度 / 参考路线长度 − 1)`。例如参考长度 100、返回 101，则 gap=1%；越低越好。用户提供的合成数据参考解没有重新做最优性认证，合法路线可能优于参考而产生负 gap。现有元数据也不足以完整识别旋转、缩放或子采样的同源实例，划分的这一限制保留。

## 7. 数值精度和训练迭代数怎样选择

数值候选为 exact、FP32、FP32 fast-math。性能面板使用固定 Static 和固定代表性 GP，各规模一次预热、五次完整计时，包含最终外部评分。在四组完整求解中都至少快 10%，才进入质量比较；按速度顺序测试，较快候选已通过时不再花评价次数测试较慢候选。

质量面板使用真正的 GPU 无 GP 对照与同一代表性 GP。先平均同实例的 5 个 seed，再计算“近似 gap − exact gap”的配对实例差值。每个规模、每种控制器的**单侧 95% Student-t 上置信界必须 ≤0.01 个百分点**。失败、缺项和非有限值不能被选择性删除；没有近似候选通过则用 exact。固定代表性表达式在查看质量结果前登记，并非从训练冠军中挑选。

训练 H 则取同时满足以下两点的最短检查点：各规模均保留从共同初解到 5000 迭代平均改善的至少 95%；24 控制器的排序相对 5000 的 Spearman 相关均至少为 0.90。无正改善、排名无法定义或所有短预算不通过，均保留 5000。阈值是我们预先选择的工程标准，不是论文结论。

Static/Rule 不使用随总预算改变的进度输入，因此可以一次跑到 5000 并保存中间点。GP 使用进度特征时，短预算会改变动作输入，不能把长运行的前缀当作短预算训练。

### 连续合成问题上的原始 FACO 适配

合成 TSP500/1000 使用连续欧氏距离，不能把坐标原样塞进 TSPLIB 的整数欧氏距离后当作同一问题。训练配对对照明确命名为 `faco_2022_continuous_identity_guard`：使用原始 double 距离矩阵，候选排序及初始化也走连续距离分支；revision 2 同时将 2-opt 恒等移动增益归零，3-opt 排除无向边集合完全不变的恒等移动，避免浮点加法重排造成虚假改善循环。没有引入正增益容差。

工程检查使用两个开发实例各 1 个 seed、5000 迭代：当前 revision 2：TSP500 gap=0.09985%、3.66 s；TSP1000 gap=0.34562%、4.97 s。这是两个实例的接口检查，**还不是整个训练/验证面板的平均 baseline**。第一次适配误保留了整数 KD-tree 候选，已保留为无效记录并排除；当前 revision 2 的证据见 [native_continuous_check.json](../../results/v2/native_continuous_check.json)。原始 TSPLIB 180 次复现不编译连续适配分支，不受该问题影响。revision 1 的两个连续检查结果另存为历史，不与新 revision 2 配对缓存混用。

下面保留前一阶段的单程序优化结果，便于区分两轮加速。

参考 [MTGP_ACO 的 CUDA 实现说明](../../../../MTGP_ACO/docs/performance/cuda_fused_architecture_20260724.md)，本轮改动包括：

- 同一面板的数据和候选驻留 GPU；n≤1500 缓存原数值距离表，避免 LS 重复开方；同一个 ACO colony 的蚂蚁共享父路线长度计算，仍按原来的顺序求和。
- 主实验规模采用一个 warp 协作一只蚂蚁、一个 block 四只蚂蚁，将 tour、位置及移动暂存放入共享内存。
- checklist 的待处理成员用直接索引标记，保持原 FIFO 和重新入队规则。
- 档案候选比较在 GPU 并行执行，保留原有平局顺序及指纹碰撞后的精确路线比较。
- 按次数运行时，批次工作量在设备端累加；最终一次传回结果，外部评分一次。生产训练不逐轮同步、下载路线或由 CPU 重新算路线长度。

距离表在 n=1000、32 colonies 时额外占约 244.1 MiB，较大规模不分配此表。当前共享内存主路径覆盖 n≤1500 的无约束求解。Hard/Escape 和更大规模保留已验证的兼容路径，不能把主面板的加速比直接套用到 E3 或 TSP10000。没有引入参考项目的 first-improvement 或其浮点容差。

另修正了浮点恒等 2-opt：相邻边被原样补回时，真增益是零；原先连续减法可能给出极小正值，反复计为改善并用尽 LS 接受次数。CPU 与 GPU 对该情况明确返回零，2022 连续对照的两个 2-opt 重载也一致修正。其他候选排序、最大增益选择与检查次数上限保留，不加入 epsilon。这个修正会改变搜索轨迹，纳入 v2 的 baseline、校准和训练；它与纯性能改动分开记录。修正前的纯优化已在同卡 128 条最终路线中保持相同无向边集合，证据见 [先前等价检查](../../results/v2/distance_cache_equivalence_before_identity.json)。

## 10. 训练前的 baseline 怎样用起来

先为完整 50 代训练面板、固定开发监控和最终验证集计算两种 FACO。这里“原始 FACO”具体使用上述 2022 连续距离适配，以保持与合成问题相同的目标。共 3200 个训练“实例×seed”成员、64 个监控成员、1024 个验证成员，每方法需要 4288 个配对位置；重复的完全相同成员/预算可复用已完成 baseline。数据库键为方法、实例编号、seed、蚂蚁数、迭代数、数值后端及初始化设置。

这些 baseline 只求解一次，使用普通编号和显式参数保存在 `artifacts/v2/protocol/baselines.sqlite`。GP 的每个个体仍完整求解；baseline 缓存不用于跳过 GP fitness。

每代会记录：冠军 GP gap、同面板原始 FACO gap、同底座 GPU FACO gap、两种改进量、实例胜率、完成 FE、实际成本。改进量定义为 `FACO gap − GP gap`，正数表示 GP 更好；胜率先在实例内平均 seed，再数改善实例。每 5 代的固定监控曲线便于比较跨代变化，训练面板变化的分数不会被误读为严格的收敛曲线。

每代额外保存实际经过的 `wall_seconds` 和这一代的 `generation_costs`，不必从累计成本相减猜测代时。wall 时间从选择面板到选出冠军，包含暂停/资源等待，尚未包含随后独立监控；GPU 求解、外部评分和 FE 另列。时间只用于观察效率，不作为训练或 ACO 的停止条件。
