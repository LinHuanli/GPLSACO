# E1完整训练冻结与独立任务并行

2026-09-09。完整FE校准已通过独立审计，主次数档采用预登记的4,096 FE。此执行协议落实v4的128个体×50代与5个演化重复，不再扩大工程pilot。正式配置见[e1_protocol_v1.json](../../configs/e1_protocol_v1.json)，无算法墙钟上限。

## 已冻结的依赖与执行顺序

GP-Full/NoFeedback的fitness不依赖Static/Rule调优结果。共同底座、FE、数据、完整776配置调优族及统一验证选择规则都已固定。因此按照v4第9.1节允许并行执行已冻结任务的原则，将完整GP训练与完整基线调优并行安排；不等待对照的最优配置后再挑训练参数。两者都继续完成各自全部预定评价，GP训练不会读取基线成绩。

这项调整只改变执行顺序。**完整G4和正式测试放行仍要求全部10个GP训练/验证结果，以及充分调参Static/Rule的选定身份经独立审计封存。** 当前允许启动的是已具备全部自身依赖的正式训练，不能因此把G4整体或E1结论标记完成。正式测试成员ID、求解seed、主要终点和统计方法先行登记，训练阶段不读测试坐标、标签或性能。

## 数据和随机重复

复用已发布的500/1K独立索引与split；不重新抽划分。训练抽样池包含500的全部63,744实例、1K的全部63,648实例，每代从各池抽16个实例；不声称50代遍历整个池。各规模验证256、测试128实例。测试数沿用此前核验后公布的全部独立原始测试成员，v4的200只是起始建议，不增加或挑选更容易的成员。训练、验证、测试与development成员互不借用。未知旋转/缩放/子采样父实例元数据和缺乏独立最优性证书的限制保持在manifest中。

演化seed严格沿用已有`gp_development.json`的1103、2207、3313、4409、5519。Full和NoFeedback各独立训练五次；不按测试结果挑最佳seed。所有条件/重复共享panel_seed 73001产生的50代实例与求解seed列表，以便配对控制评价噪声；演化RNG独立于面板RNG，五个演化seed控制各自初始化、选择、交叉、变异。相同面板不等于五个演化过程共用演化随机状态。

每代每规模16实例×2 solve seeds，32 colony×32 ants；每个体均重新完整评价两规模，包括精英和重复树。最后一代必须评完。冻结阶段将全部成员表及50代面板写到项目内artifact并保存SHA，真实训练每代在提交前核对其面板与预登记一致。冻结阶段只枚举split ID，不读取标签或坐标。

## 演化、选择与评价工作量

沿用已验证的标准DEAP varAnd、深度1–3初始化、最大深度5/节点63、锦标赛4、精英4、交叉0.8/独立变异0.2。NoFeedback在生成grammar时删除1/2/3三个反馈终端，保留feature_spec_id=2及其余原编号；不是事后屏蔽Full程序的输入。基础图仍为E1无约束共同FACO-Control，不从E3结果选择主图。

每个演化重复完成6,400个fitness评价、12,800次原生面板调用、1,677,721,600 search-tour FE。10个训练共16,777,216,000 FE；这是预定工作量，不是时间上限。验证另计：去重的各代冠军加最终种群，每个候选完整评价两规模各256实例、seed 17/29、4,096 FE。不会因短名单较大而缩减成员或只验证第一名。

共同初始化不扣搜索FE。构造步、LS移动检查、注册/传输/控制/求解/外部评分和总CPU/GPU时间继续记录。最初九个训练采用A5000、driver 610.43.02及同一原生二进制；每运行固定GPU UUID，恢复不能静默迁移。图分支和其他实现保留独立工作树，不改活动基线/训练的源码与二进制。

用户随后明确补充“只要是空闲的GPU就都可以用”。依此登记[硬件补充协议](../../provenance/e1_hardware_amendment_v1.json)：后续任务可使用其他空闲兼容型号，原50代面板、五seed、FE、演化/验证规则和统计协议不变。`gpu-free`负责发现，worker仍核查实际UUID占用并持有项目设备锁。新型号先记录兼容验收；计时按型号/driver分列，不把混合设备时间合成加速比。既有九运行保持原身份，不改冻结文件，也不以硬件调整为由重跑。

首个新增型号PRO 5000 Blackwell复用同一b4138774二进制，通过次数及基线原生检查、8项Python检查；相同10个32-colony开发任务的320条路线/成本、全部控制状态、FE和内部工作量与先前A5000记录逐项一致，见[验收记录](../reports/e1_pro5000_compatibility.json)。有限面板一致不是所有输入的跨硬件一致性证明；此限制与实际型号须随最终结果保留。

## 测试和统计先行登记

主终点为4,096 FE下的reference gap。1,024与16,384为补充；10个合成solve seeds为17、29、41、53、67、79、97、109、127、149。先在实例内平均solve重复，再在每规模内平均实例，最后两规模等权；全部五个GP演化重复逐个报告，另给总体效果。正方向定义为对照gap减Full gap。

主比较只有Full对Static、Rule、NoFeedback三项，Holm校正。实例簇bootstrap 10,000次，按规模分层，95%区间，统计seed 20260909；另报告同时重采样训练seed的两层敏感性分析。双侧配对符号置换以实例差为输入，100,000次，seed 20260910，使用加一Monte Carlo p值；方法和对称零假设的适用范围须随最终结果说明，不把solve seeds当独立样本。完整任务失败不得从主比较中剔除。

本配置只冻结E1主训练/比较；状态分叉机制、原生外部参照以及E2–E4的各自协议仍须完整实施，不因主训练启动而省略。

## 运行与终态

`scripts/research_e1.py freeze`要求完整FE审计、冻结次数决定和真实完整基线调优manifest，再固定自身源码、共同二进制、配置、成员和面板身份。`train`只接受上述两条件/五seed，复用原有TrainingRun与持久worker；不提供缩短代数、减少个体或限时选项。

新增封装只检查预登记面板和GPU任务边界：占用发生在提交前则保留待办；任务返回后的资源查询失败仍先保存实际结果。Future观察超时等待原任务，普通失败不重复挑选。后续独立训练审计必须重放原始演化/面板RNG、全部实际fitness、短名单/验证选择、计数与资源，并明确这些结果属于正式训练而非测试结论。
