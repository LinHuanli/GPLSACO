# 代际训练、费用与恢复契约 v1

本文件将v4 Algorithm 2及11.8–11.9转成状态机要求。开发pilot可以减少种群/代数并使用预登记开发数据，但每个个体仍使用同一完整精度、同一固定形状和同一预算。pilot不是正式E1训练；正式参数和费用仍需G4冻结。

## 基本代际与随机数

演化使用DEAP `genHalfAndHalf`、`cxOnePoint`、`mutUniform`和真实 `algorithms.varAnd`。初始深度1–3，子树变异表达式为 `genFull` 深度0–2；都作为配置保存。联合深度≤5、节点≤63谓词交给一次 `gp.staticLimit`，超限时均匀选原父代完整回退，不修剪。装饰器只能收到个体位置参数，计数器名称/算子函数不得预绑定成位置参数，否则DEAP会把它们加入候选父代。

锦标赛有放回抽取4个个体，以fitness、节点数、IR hash的精确字典序选择。精英按同一规则选4个并克隆；其余父代交给varAnd，0.8交叉后再以0.2独立变异。新面板开始时全部fitness失效，重复树也按实际个体位置执行，不缓存其成绩。全部当前代个体完成之后才保存冠军及生成后代；最后一代保留已评价种群。

演化RNG和面板RNG为两个独立 `random.Random`。调用依赖模块random的DEAP算子时临时切换状态，结束后恢复协调进程原状态。算子与ERC使用演化流，面板和solve seeds使用面板流，任务到达顺序与GPU时间不消耗演化流。本实现不使用NumPy随机发生器生成演化/面板数据，因此无额外未保存NumPy RNG状态。

## 固定准备费用

checkpoint恢复会重新创建worker、重新测量CPU准备。若继续使用新测量费用，同一代的已完成和未完成个体会得到不同可用搜索时间，因此缓存费用不能只留在worker内存中。

在任何面板的第一个个体评价之前，协调进程通过worker准备无标签问题，记录每实例廉价/昂贵准备费用；首次记录后在本run中冻结。费用与坐标身份、配置和来源一起进入checkpoint。每个cached任务显式携带完整费用表，表进入task ID；worker在原生Engine中设置只可赋一次的对应扣费。原始实测准备时间继续单列，不能被冻结值覆盖。

恢复后仍重新执行实际必要的准备，但使用checkpoint中原有费用扣预算。`end_to_end`继续在原生调用内重做准备且不另外扣费，不接受无用途的冻结表。未提供费用表的旧开发调用仍可使用实测费用；已经赋过冻结费用的worker实例不能在后续cached任务中悄悄省略表。

训练与验证各阶段开始新worker，容量至少覆盖该阶段可能使用的所有问题，避免个体评价过程中发生缓存重建改变准备费用。worker通用容量保护仍保留，正式执行由配置验证杜绝阶段内溢出。

## checkpoint与任务提交

采用带版本和SHA256内容摘要的JSON checkpoint，同目录写临时文件、fsync、原子replace并fsync目录。保存IR/常数位模式、fitness有效标记、当前面板身份、代数、冠军列表、算子计数、演化与面板RNG、已确定的实例/seed/预算/费用、活动任务列表和已完成结果表、软件/数据/硬件身份及成本累计。

摘要针对JSON往返后的实际结构计算。整数规模键转换为字符串后，排序顺序可能变化；转换造成的重复键直接拒绝，不能静默覆盖。首轮pilot的独立归档复核暴露过此问题，失败产物保留，回归用例覆盖500/1000键的往返和整数/字符串混合键冲突。run manifest及完整数据成员表先写入，再发布首个checkpoint；恢复同时核查这两个归档。

重建DEAP树只使用验证后的postfix IR和当前grammar节点，不eval树字符串、不加载pickle。ERC在恢复树中成为相同FP32值的数值终端；本配置只作子树变异，恢复前后IR及未来遗传操作必须一致。+infinity以显式有效标记和null值编码，禁止JSON NaN/Infinity。

任何准备或求解提交之前先持久化对应任务身份。原始任务结果和完成记录的写入顺序必须允许识别“结果已落盘但checkpoint尚未前进”的窗口；恢复时校验身份和hash后归集既有结果，不能把已完成工作当作新随机样本。观察Future超时继续等待原句柄，不能据日志延迟重启。

实际实现有三步原子写入：worker返回的receipt、独立核验后的receipt、checkpoint完成表。三个窗口分别注入中断测试。无效准备返回仍写入receipt，恢复后保留同一错误，不当成进程故障再执行。非有限返回数值用显式非法数值标记保留，外部fitness判失败，JSON不写NaN或Infinity。每个出现过的IR及每代完整已评种群单独归档；这是程序身份存储，不能用于跳过重复个体评价。

只有确认worker进程终止/进程池损坏的基础设施失败可以按冻结次数重试同一任务；普通输入/求解失败保留为失败成绩。恢复只承诺任务、费用、配置和随机状态一致，不承诺wall-clock截止轨迹逐位相同。

一个目录同时只允许一个协调进程持有flock。恢复时旧worker PID仍存在则不提交；活动Future继续原句柄等待。默认基础设施重试1次，耗尽时整个预定面板为失败，另一规模仍完整执行。没有形成有效费用表的准备/数据错误停止该run，保留错误receipt供排查，不生成虚构费用。

## 验证与导出

shortlist是各代冠军和最终已评种群按IR hash去重后的集合。所有候选使用同一固定验证实例/seed/预算/费用，按验证fitness、节点数和hash选择；不使用跨代不同训练面板成绩选全局冠军。保存全体候选结果与失败，最终导出可读表达式、规范IR、数值/终端规格、mask、solver/worker/data配置及hash。没有有限验证成绩时不得导出一个伪装为成功的选中程序。

验收以实际测试/运行报告为准，不能由本契约或仅使用假evaluator的测试推断训练已经完成。

当前`train_gp.py`只开放显式开发池pilot，配置见`configs/training_pilot.json`。开发训练池每规模48实例，独立开发验证池16实例；两者均属于已暴露development，不读取正式测试成绩。主研究128×50、至少五个演化seed保持原计划，预算和共享准备费用协议待G4校准。现有成本累计涵盖worker、外部evaluator、原生调用/扣费/超限和启动记录；完整协调开销、十二特征/档案分项剖析还需补齐。
