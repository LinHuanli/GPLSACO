# E1 状态分叉的次数接口与验收边界

本文规定机制实验所需的实现契约；正式采样实例、状态阈值、来源程序、分叉 seeds、每层数量和继续策略仍须在机制结果产生前另行冻结。E1 主训练、基线与 E3 正在原冻结工作树中运行，本工作在独立 `work/e1-state-fork` 分支完成。

## 次数与状态

源轨迹的 progress 始终等于其已完成 FE / 原完整源预算。快照可以在预定完整蚂蚁批次边界产生，不能通过缩短 progress 分母改变源轨迹。继续阶段使用相同原分母及原批次编号，返回账本只记录本次新增 FE；源前缀 FE 单独记录。机制比较以相同额外 FE 取代 v4 及 E1 草案中的相同额外时间，不设置算法墙钟上限。

快照包含所有持久算法显存缓冲、主机已提交 incumbent、形状、配置、实例与原 seeds、批次编号、完整源预算、实验 mask。至少覆盖参考/epoch/global tour 及逆位置、档案与工作缓冲、信息素边值/default/cache、控制反馈与身份、所有 ant tour/visited/pending/LS 工作状态、随机 key、候选/坐标/归一化/采样节点以及当前区域和动作特征。一次同步后才发布快照；命名缓冲的累计字节数必须与全部生产缓冲分配量相等。剖析 event 与耗时不属于算法状态。

在源 key 和下一个批次编号下，预先计算下一决策的区域；区域计算不能修改参考解、档案或反馈。快照只在完整批次的提交边界产生，不在运行中的 CUDA kernel 内截取。持久化格式固定版本、长度和校验，读回时验证形状、配置、源预算、数据与所有缓冲；正式运行还须由外部 manifest 固定源码/native SHA256。

## 配对干预

每个分支都完整恢复原快照；恢复原 keys 且无干预时，继续源控制器应与未切断轨迹一致。机制干预使用配对 seed 派生相同的新随机 keys，保留原批次编号。第一批强制保持参考解、使用快照中同一区域，只有 MNE 2/16 不同。第一批之后应用同一个预先固定的继续策略，区域、反馈、档案与信息素按普通规则演化。两分支不得继承彼此状态。

若提取单个 colony 以保存/执行样本，必须保留其全部缓冲和随机 key；特征采用 feature-major 布局，不能把它误当作 colony 连续数组切片。单 colony 继续与原面板对应成员须另行核验，不能凭分配形状推断轨迹等价。硬件/批形状及快照 I/O 耗时与主速度比较分开登记。

## 必须通过的工程验证

1. 多个切点（含零 FE）的保存、序列化、重建 Engine 和无干预继续，核验动作、特征、反馈、档案、信息素、全部合法 tour 和工作量与未切断源轨迹一致。
2. 更换程序和其他任务污染缓冲后再恢复，原快照不变；A–B–A 分支重放一致，顺序不影响结果。
3. MNE 配对第一批的参考、区域、信息素/default/cache 及随机输入一致，只有目标阈值不同；两分支新增 FE 严格相同。
4. 拒绝损坏、缺缓冲、配置/实例不符、非整批 FE 和越过源 progress 预算的恢复。诊断延迟不改变次数或轨迹。
5. 在实时空闲的兼容 GPU 上核验完整 32×32 形状及 500/1K 开发实例，再进行 CUDA 内存检查。工程验证不得替代正式分层采样与机制结论。

正式机制采样只使用开发实例，独立 pilot 的 q/c 分位数规则先冻结，缺层如实报告；来源控制器由既定开发/验证流程确定，不能选择有利快照或按分叉收益调策略。统计以基础实例聚合，来源分层，限定于实际样本和固定继续策略。
