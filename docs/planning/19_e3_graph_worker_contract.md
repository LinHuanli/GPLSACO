# E3 图目录与常驻 worker 契约

本工作包在真实worker运行前登记。承接匹配v2及Escape v1，所有更改位于独立E3工作树，既有E1训练和基线调参继续使用原实现。此处工程检查不能替代正式四条件独立训练。

现已完成[真实worker矩阵与四条件开发训练/恢复验收](../reports/2026-09-09_graph_worker.md)。正式全量图准备和训练协议仍待完成。

一个worker固定先验类型和限制模式。协议冻结图目录文件的路径与完整SHA256、图格式1/匹配规则2/Escape规则1、原生二进制、Python实现、固定batch shape及实际host/UUID/型号/driver。目录精确列出无标签实例身份、坐标摘要、匹配缓存文件及其摘要、两个先验的图摘要与边数。求解器只接收坐标与已核验的六字段图资料；图目录不含标签或标签路径。

任务与准备身份包含所需图的完整摘要。实例uint64键仍取坐标摘要前64位，不能将先验/模式混入该键而改变原生随机流。同一worker缓存中的键须同时对应原坐标与冻结图身份；碰撞或内容变化明确失败。新图第一次读取核验全部文件字节和图摘要，已注册实例复用同一原生准备状态。缓存只在已有容量策略规定的任务边界重建。

Hard/Escape仅允许evaluation-count入口，不允许同时带秒数上限或准备扣费。原生end_to_end重做Engine内部准备，外部LKH先验与匹配已缓存，其一次性费用另列，不能将这称为包括LKH的总端到端成本。训练与基线配置搜索复用同一协议和任务类型；四条件分别创建协议和训练运行，不能复用其他条件的fitness或已选程序。

独立外部评分检查原生返回限制模式、图格式/边数、Escape版本/容量及FE账目，并对Hard逐条返回tour核验E0可行性。零FE必须返回共同初解。Escape允许图外边，完整逐移动许可由已完成的原生oracle检查覆盖，不能把只检查最终tour写成全轨迹证明。

所有工作树共享主Git仓库下按GPU UUID命名的锁；spawn子进程独占设备，启动前检查实际占用。观察Future超时继续等待同一次提交，不转为求解时间上限。输入错误保留失败记录；同一PID的GP/Static切换、重复求解、准备/求解身份、目录损坏、恢复拒绝以及缓存容量边界均需针对性验证。新工程运行先保存真实返回，再做可能失败的设备查询及外部评分。

工程运行曾在上一条件释放GPU后因空闲读数未达阈值停止下一次启动。后续持锁等待空闲读数，循环重查外来进程，出现外来计算任务则拒绝启动；等待记录进入runtime，不将其转换为求解时间上限。原失败日志和源码继续保留。

正式训练冻结前还需预先准备全部采样面板与完整验证成员的两先验图，并独立审计其来源/匹配；本契约只接通该数据通路，不自动放行正式E3或TEST。
