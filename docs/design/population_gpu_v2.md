# GP 种群的 GPU 并行与本次提速

当前科学范围是 TSP500 训练、三个独立 GP seed、128 个体 × 50 代；每代 16 实例 × 1 ACO seed。完整实验规则见[当前协议](../experiments/round_three_seed_v2.md)。TSP1000 只在最终程序冻结后作迁移测试。

## 1. 实际并行层次

| 层次 | 当前配置 | 执行方式 |
|---|---:|---|
| GP 独立重复 | 3 | CPU 协调器独立提交、共享全部可用 A5000 |
| 一代个体 | 128 | 整代提交，可拆为 16/32/64/128 个体的独立分片 |
| 训练实例/求解 seed | 16 × 1 | 每个体 16 个独立 colony |
| 蚂蚁 | 每 colony 128 | 一个 warp 协作一只蚂蚁，一个 block 四只蚂蚁 |
| 完整 128 个体 grid | 2048 colonies、262144 蚂蚁、65536 blocks | 实例几何共享，个体状态独立 |
| 32 个体分片 grid | 512 colonies、65536 蚂蚁、16384 blocks | 各分片可由任意空闲 worker 执行 |

展开表示所有任务进入同一 grid，由 GPU 分批调度 blocks，不意味着所有线程同时驻留片上。ACO 的特征、评分、动作、构造/LS、档案和信息素更新仍有内核边界；生产路径不逐迭代同步 CPU。

借鉴 [RMTGP CHANGELOG](../../../../MTGP_ACO/CHANGELOG.md)、[融合实现](../../../../MTGP_ACO/src/rmtgp_aco/cuda/aco_fused.cu)和 [tiled v2](../../../../MTGP_ACO/src/rmtgp_aco/cuda/aco_tiled_v2.cu) 的 program×instance 任务索引、数据常驻、独立工作区和批量返回。本项目的 checklist LS 保留最大增益选择、FIFO 次序和原平局规则；没有为了提速改成 first-improvement 或近似距离。

## 2. 为什么之前慢，本次优化了哪里

对真实首代的 128 个体 × 16 个 TSP500 开发实例 × 1 seed × 100 迭代做生产 CUDA event 测量，记录的是整个种群，不能再乘 128：

| 内核阶段 | 优化前毫秒 | 优化后毫秒 | 含义 |
|---|---:|---:|---|
| 构造 + 局部搜索 | 15530.23 | 11153.46 | 最大开销；GP 评分本身不是瓶颈 |
| 档案与反馈更新 | 5646.42 | 465.81 | 大量相同路线的重复比较得到消除 |
| 区域特征 | 293.05 | 110.38 | 并行节点贡献与按程序需求计算 |
| GP 表达式评分（优化前） | 0.974 | — | 重新给每棵树编译专用内核收益有限 |

生产路径总计时还包括其他内核、返回和外部评分，不能把此表简单当成端到端时间。

本次保留算法语义的改动：

1. 规范路线比较直接按 tour 数组的位置与方向读取，避免沿位置表追踪；档案排序复用一次三向比较。候选若已与选中的路线重复，就不在后续档案槽重复检查。算法原有指纹仍用于快速筛选，最终精确比较仍保留。
2. 区域特征由线程各算节点贡献，再按原节点顺序累加，保留浮点加法次序。程序未读取的区域统计无需计算；有解释采样时强制计算全量 12 特征。
3. 节点重定位只复制发生改变的闭区间。2-opt 在受影响区间内成对交换，保持直段、环绕段和位置零的原语义。
4. 每线程的 LS 候选增益保存在寄存器，warp shuffle 归约最大增益；相等时仍按原索引选取。正增益胜出后才读取移动端点。
5. 共享 GPU worker 复用上下文。分片完成后直接接单，每 60 秒才发现新的空闲卡，不因每个分片完成而反复扫描集群。

没有改变距离精度、RNG 域、评价预算、初始化条数、LS 接受条件或完整代际屏障。

## 3. 实测速度与显存

同一张 cuda07 A5000，同一首代种群和开发面板，均包含一次外部最终路线评分：

| ACO 迭代 | 优化前秒 | 优化后秒 | 加速 |
|---|---:|---:|---:|
| 100 | 22.0760 | 12.3774 | 1.78 倍 |
| 1000 | 252.6614 | 137.5215 | 1.84 倍 |

100 迭代采用热身后的三次中位数；1000 迭代长预算各测一次。2048 条最终路线、成本、档案状态、构造/LS 工作量、FE 全部直接相等。比较前构建是 `build/v2-tsp500-reference`，优化后是 `build/v2-tsp500-exact`；两者使用同一 exact 数值设置。

单卡顺序执行相同 128 个体、H=100 的分片比较，包含外部评分：

| 每片个体 | 完成全部 128 个体的中位秒 | 引擎设备数组 |
|---|---:|---:|
| 16 | 14.0893 | 327951424 bytes |
| 32 | 13.2779 | 618170496 bytes |
| 64 | 12.9463 | 1198608640 bytes |
| 128 | 12.8368 | 2359484928 bytes |

全种群约 2.20 GiB，不包括 CUDA 上下文和其他缓存。32 个体分片约 0.576 GiB。测试 TSP1000 的内存单独按实际面板记录，不能套用 TSP500 数字。

最终分片以共享池的总完成时间选择，单卡表只用于解释调度与占用率的权衡。三个真实 GP 首代、全部 6144 次 ACO 求解在同一开发面板上执行。H=100 的单卡表采用热身后三次测量；最终共享池在固定的一组 A5000 上，以 H=1000 对每种分片各测一次完整预算，包含派单、返回和外部评分。长预算单次测量的差异不应解读为稳定的精确加速比例。完整测量与所选值记录于 [tsp500_performance.json](../../results/v2/tsp500_performance.json)。这是吞吐工程检查，不是训练或测试成绩。

固定三张A5000、三个GP首代合计786,432,000 FE的实测总完成时间：

| 每片个体 | 三个种群总完成秒 |
|---|---:|
| 128 | 151.201 |
| 16 | 195.813 |
| 32 | 152.804 |
| 64 | 148.802 |

128个体分片距最快的64分片约1.61%，位于预设3%容差内，因此本轮选择128。三个进化seed在共享队列独立推进；此测量同时完成三个首代，不能把151.2秒再乘3来估算三次并行进化。

137.52 秒相当于开发面板上单卡种群评价约 2.3 分钟。正式每代还包括分片传输、共享池等待、评分、繁殖和快照；后期程序的动作也可能改变 LS 工作量。报告显示真实每代用时，不再用旧双规模双 seed 的预算估算当前轮次。

## 4. 状态与恢复

随机数只由问题 numeric_id、ACO seed 和算法随机计数决定，个体索引、GPU UUID、分片大小不进入随机域。相同程序/实例/seed/预算在不同 GPU 和分片下保持同一轨迹，重复程序仍完成各自全部 FE。

GPU 返回原始分片结果，CPU 协调器按原个体顺序归集并评分。日记记录已评分结果及原始分片路径/成员下标，不把完整 tour 再写一遍。重启可读取已完成分片与日记，既不重跑已完成求解，也不重复评分；不同代仍重新评价。

一张 GPU 同时只有本项目一个 worker。邮箱绑定进程 PID 和启动时间，避免重启后执行旧请求；共享 worker 在无任务时退出并释放 GPU。退出的等待只控制空闲资源占用，不是算法时间预算。算法或数据失败不能按效果丢弃；基础设施故障最多重试一次。

所有写入留在本项目内。文件、代码、程序身份、检查点和实验管理没有完整性哈希。已有合法形状检查、CUDA 错误处理、必要的外部最终评分保留。

## 5. 验证范围与边界

20 个当前 CUDA/C++ 检查通过。新旧构建分别在两张 A5000 上检查 TSP500/1000，比较完整路线、状态、FE、构造/LS 工作量；单程序、3/5 个体分片和完整种群结果一致。稀疏决策采样提供的实际 12×32 特征可以重算出对应 32 个分数及动作。

完整工程流程为 3 seed × 2 代 × 8 个体，训练 H=10，快速验证 H=10，最终验证与测试 H=20。已在两张 A5000 上完成 91 项任务，包括三次训练、两级验证、冻结、两规模测试和解释，无失败。它只说明数据流与依赖正确，不证明正式 GP 改善。

最终验证记录与 Python 回归结果见 [tsp500_verification.json](../../results/v2/tsp500_verification.json)。当前构建关闭不使用的旧 2024 adaptive FACO 适配目标；作者 baseline 另用 2022 `faco_2022` 连续适配构建。普通种群路径适用于 n≤1500；图约束和更大实例继续使用各自兼容入口。
