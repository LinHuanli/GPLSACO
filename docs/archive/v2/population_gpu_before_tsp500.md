# GP 种群在 GPU 上展开

普通 TSP500/1000 的 GP 训练和候选验证使用 `FacoBatchEngine(..., population_size=128)`，一次提交整个种群。每个个体保留独立的信息素、路线、档案和反馈，全部完成自己的 FE。每代两个规模分别执行一次。

## 并行布局

| 层次 | 主训练配置 | GPU 表示 |
|---|---:|---|
| GP 个体 | 128 | 128 份程序 IR，评分 warp 按个体索引取程序 |
| 实例 | 每规模 16 | 坐标、候选和距离表常驻 GPU |
| 求解 seed | 每实例 2 | 每个体 32 个独立 colony |
| 蚂蚁 | 每 colony 128 | 一个 warp 协作一只蚂蚁，一个 block 四只蚂蚁 |
| 一次展开 | 4096 colonies、524288 只蚂蚁 | 构造/LS grid 共 131072 个 blocks |

“展开”表示一次 grid 包含所有逻辑任务；GPU 按 SM 容量调度 blocks，并不要求五十多万只蚂蚁同时驻留片上。每次 ACO 迭代仍有设备内核边界，控制特征、评分、动作、构造/LS、更新依次执行；生产循环不逐迭代同步 CPU。

借鉴了 [RMTGP 更新记录](../../../../../MTGP_ACO/CHANGELOG.md) 和 [融合 CUDA 实现](../../../../../MTGP_ACO/src/rmtgp_aco/cuda/aco_fused.cu) 的 program×instance 任务索引、实例数据常驻、独立工作区和批量返回。其 0.5 融合版本一个线程负责一只蚂蚁、一个 block 内完成整个 colony；后续 [tiled v2](../../../../../MTGP_ACO/src/rmtgp_aco/cuda/aco_tiled_v2.cu) 已按 population×instance×ant×candidate 分层，并拆分构造和更新内核。本项目采用可扩展的分阶段网格；FACO 的路线翻转和 checklist LS 由一个 warp 协作处理，保留原来的数值和最大增益移动规则。未采用其 FP32、first-improvement、行为去重或时间预算。

## 怎样装进 A5000

不可变数据按 32 个 instance/seed 面板槽存储，由 128 个个体共享。当前两个 seed 的几何数据仍各占一个槽，种群维度不复制距离表。动态 colony 编号为 `individual * 32 + replica`，几何槽为 `colony % 32`。

- 路线、位置和移动暂存在每只蚂蚁的共享内存中使用 16 位节点；最终路线/位置按原格式写回，供档案更新使用。
- 父路线位置表由同 colony 的蚂蚁共享，省去逐蚂蚁副本；全局 scratch 也不再为这一生产路径分配。
- checklist 用容量 n 的环形 FIFO。queued 标记保证同时等待的节点最多 n 个；出队时清除标记，允许之后重新入队。次序、重入队和 LS 上限保持不变，诊断路径仍保留完整历史工作区。
- 重启动作重置算法状态；构造内必然覆盖的临时数组不再提前重复清空。

初测引擎数组：TSP500 为 4.395 GiB，TSP1000 为 8.643 GiB，合计约 13.038 GiB。加上单程序监控引擎和 CUDA 上下文，能容纳于 24 GiB A5000。数组大小不等同于整个进程显存。

## 随机数、FE 与恢复

随机 key 继续只由实例 numeric_id 和求解 seed 派生；个体编号、放置位置和分块数不进入随机域。同一程序、实例、seed、预算在单程序/种群路径下应得到相同结果。重复程序仍占独立列，每项都构造全部预定路线。

每个个体每规模完成 `32 × 128 × H` FE，一代两个规模合计 `128 × 2 × 32 × 128 × H` FE。GPU 累计构造和 LS 工作量，最终按个体返回。整批实测耗时等额分摊至成员，同时保留整批耗时，避免总账重复计算并行成本。

一个完整种群批次的结果和评分在 `results.jsonl` 中作为一条记录保存。逐个体使用“字节位置、成员下标”定位；恢复已落盘批次不重新求解成员。聚合只读取紧凑评分，避免为每个个体反复解析整个种群的路线。跨代新 occurrence 始终重新评价。

worker 只在启停时写一个小型 PID 记录，防止首代大快照尚未更新时误启动重叠任务；不做每任务 GPU 扫描或完整状态快照。

`--stop-after-tasks` 是人工暂停的观察边界；若阈值落在 GPU 批次中间，等待整批完成和保存后暂停，不缩短算法 FE。训练不设置墙钟截止，不创建文件或运行记录的哈希。

## 范围与检查

当前种群入口用于 n≤1500、无图约束的 Full、NoFeedback、M10、M01。固定监控单程序沿用原入口；候选验证也使用种群入口，多于 128 时分块。Hard/Escape 的 E3 和更大规模继续使用兼容入口，不套用这里的速度数字。

种群参数表示预分配的最大容量。验证尾块和恢复剩余成员可以提交较少程序，沿用已有缓冲；只有活动成员进入 GPU grid，不填充虚假个体、不增加 FE。这样不必在 128 个体主块和较小尾块之间反复释放、分配数 GiB 显存。

针对性检查包括不同程序、重复程序、两组实例/seed、M10/M01，以及单成员和非法形状；逐个体比较完整路线、成本、反馈、构造/LS 工作量及 FE。真实 worker 检查覆盖两代训练、批次暂停恢复和候选验证。工程检查不作为 E1–E4 的质量结论。

最终构建在 A5000 上通过 CTest 20/20 和 Python 259 项检查（0 跳过）。完整 worker 检查使用 128 个体、每规模 16 实例×2 seeds，完成两代训练及 113 个候选验证；总计 964 个成员求解、57,999,360 FE，失败和重复评价均为零。这个检查只取开发数据，训练 H=10、验证 H=20；人工暂停恢复也计入首代实际经过时间。证据见 [代码验证](../../../results/v2/verification.json) 和 [完整种群流程检查](../../../results/v2/population_training_check.json)。

完整种群测速在同一张空闲 A5000 上比较两个入口，均包含一次外部最终路线评分。首代使用进化 seed 1103，保留全部 128 个体，不做行为去重。最新测量见 [实验说明第 9 节](../../reports/实验说明与结果.md)，原始输出位于 `artifacts/v2/gpu-checks/population-*.json`。
