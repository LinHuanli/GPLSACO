# 本轮实验：三个 seed、50 代、两类 FACO 对照

本轮回答三个具体问题：GP 能否随进化改善训练和验证表现；最终学到了怎样的控制表达式；在独立测试集上相对 FACO 提升多少。设置按用户 2026-09-09 的最新要求固定，主报告为[三次进化实验](../../reports/三次进化实验.md)。

本轮只运行 Full GP 三次独立进化。NoFeedback、完整 Static/Rule 搜索及 E2–E4 留在后续研究中；小规模工程检查不计入本轮科学结果。原始 FACO 的六个 TSPLIB 实例、各 30 次复现属于此前独立实验，不能与本轮连续距离数据混合统计。

## 1. 参数、预算和依据

| 参数 | 本轮设置 | 依据 |
|---|---|---|
| 进化 seed | 1103、2207、3313 | 用户要求三次独立进化；取已登记序列的前三项 |
| 种群、代数 | 128 个体，50 个完整评价代 | 用户确定 50 代；128 是预先登记的实验与 GPU 并行配置，不宣称最优 |
| 精英、锦标赛 | 精英 4，锦标赛大小 4 | 沿用当前 GP 协议；保留少量优胜个体并控制选择压力 |
| 交叉、变异 | 0.8、0.2 | 沿用当前 GP 协议；这是设计选择，不来自 FACO 论文 |
| 树约束 | 初始深度 1–3，变异子树深度 0–2，最大深度 5，最多 63 节点 | 控制表达式复杂度和在线评分成本 |
| 特征 | Full、feature spec 2，12 个输入 | 当前搜索状态与候选动作描述；参考标签不进入 GP 或求解器 |
| 蚂蚁数 | `64 × ceil(sqrt(n)/16)`，TSP500/1000 均为 128 | 2022 原始 FACO 论文主性能比较设置，依据见[参数说明](../../design/implementation_v2.md) |
| ACO 基础参数 | beta 1、信息素保留率 0.5、主/备用候选 16/64、LS 候选 20、p_best 0.1、epoch source 概率 0.01 | 继承版本的基础参数；GP 的 MNE 选择为 2/4/8/16 |
| 验证、测试 ACO | 5000 次迭代，即每次求解 640000 次构造路线评价 | 与论文主实验迭代数一致 |
| 训练 ACO | H 待现有开发曲线完成后冻结 | 最短预算同时保留到 5000 迭代改善的至少 95%，且两个规模排名相关均 ≥0.90；否则 H=5000 |
| 数值后端 | exact；构建 `build/v2-campaign-exact` | 既有质量/速度选择保留 exact；新构建加入整种群计算和稀疏决策记录 |
| 停止标准 | 评价次数；不设算法运行时间上限 | 用户要求；SSH 管理查询超时不属于算法预算 |

每代在 TSP500 和 TSP1000 各抽取 16 个训练实例，每实例两个求解 seed，因此每个 GP fitness 包含 64 次独立 ACO 求解。50 个面板由 seed 73001 预先生成，三个进化 seed 使用同一序列。

训练一次进化包含 `128 × 50 = 6400` 次个体评价、409600 次 ACO 求解，训练主预算为 `52428800 × H` FE；三次进化合计 `157286400 × H` FE。这些数值不含监控、完整验证、baseline 和测试，它们分别记账。精英、重复表达式和后来再次出现的个体都重新执行本代评价，不复用 GP 训练 fitness。

## 2. 哪些数据做什么

数据来自既有 `main-index-v1`，保持连续欧氏距离。标签只交给求解结束后的外部评分器。`gap = 100 × (cost/reference − 1)`；reference 是用户提供的参考值，不新增“已独立证明最优”的主张。

| 用途 | 每个规模的成员和求解 seed | 使用方式 |
|---|---|---|
| 训练 | 每代 16 个 train 实例 × 2 seeds，50 代 | 面板变化；评价所有 128 个体 |
| 固定开发监控 | 既有声明的 16 个 development 实例 × 17/29 | 每 5 代评价当代冠军；5000 迭代 |
| 完整验证 | 256 个 validation 实例 × 17/29 | 所有不同的代际冠军及最终种群，5000 迭代 |
| 正式测试 | 128 个 test 实例 × 17/29/41/53/67/79/97/109/127/149 | 三个程序全部冻结后才评分，5000 迭代 |
| 个体解释 | 每规模前两个固定监控实例 × seed 17 | 冻结后独立回放完整 5000 迭代，不用测试成绩选择例子 |

完整成员及 seed 保存在本轮 `panels.json`；它从看结果前已经登记的 v2 面板复制。开发预算标定继续使用此前 `[96,128)` 实例、24 个控制器和 5 个求解 seed，不与训练、完整验证和测试混用。

训练曲线报告每代冠军、种群平均、中位数，以及同面板两类 FACO 的 gap。固定监控形成每 5 代可比曲线。训练结束后，从完整验证结果重建全部 50 个代际冠军的验证曲线；相同表达式的验证结果只计算一次并映射到对应代。

每次进化按完整验证宏平均 gap 选择最终程序，同分依次选节点更少者、普通程序编号更小者。必须三个程序都选完并写入 `methods_frozen.json` 后，才能开始任何正式测试评分。测试不会再选择三者中最好的一棵作为唯一报告结果。

## 3. 两类 FACO baseline

| 对照 | 设置和用途 |
|---|---|
| 作者 FACO 2022 连续距离适配 | 作者构造与原生局部搜索，MNE 8，论文蚂蚁数，8 个 CPU 线程、24 条原生初始路线；连续适配 revision 2。回答相对作者算法的表现。 |
| GPU FACO 无 GP | 与 GP 共用距离、初始化、checklist 2-opt、exact 后端；MNE 8、全路线均匀起点、不重启。回答 GP 控制本身带来的改善。 |

GPU 底座采用节点重定位，不宣称与作者实现逐步等价。完整参数声明和适配说明见[实现说明](../../design/implementation_v2.md)。原生对照在多主机上并行，每台主机同时最多一个 8 线程任务。只接纳实际具有 24 个逻辑 CPU 的主机，以保持作者的 24 条初始化路线；其他主机仍可执行 GPU 任务。cuda07 是初始 CPU 主机，新主机由空闲 A5000 发现过程登记；cuda08、cuda10 的两规模检查与 cuda07 得到相同完整路线。

训练前，两种对照都必须覆盖训练、监控、验证：每方法 3200 个训练位置、64 个监控位置和 1024 个验证位置，共 4288 个配对位置。训练对照使用 H，监控/验证对照使用 5000。相同成员可共享 baseline；覆盖确认后发布只读数据库，三次训练共用，不在训练循环中重复检查文件或计算哈希。

固定 5000 迭代的监控/验证对照在 H 冻结前即可开跑，与开发标定同时排入多卡、多主机队列。H 冻结后追加训练对照；固定对照的任务编号和结果保持原样，不重新计算。所有训练对照齐备后，三个进化 seed 同时竞争空闲卡；有三张可用卡时就同时开始三次训练。

正式测试重新执行同一测试面板上的三棵 GP、GPU FACO 和原生 FACO。GP 与 GPU FACO 分别计时，分片轮换四个 GPU 方法的执行顺序，避免把并行多个 GP 的摊销收益误记为单方法速度。

## 4. 怎样判断提升

先在每个实例内平均 10 个求解 seed，再平均实例；TSP500 与 TSP1000 等权。主报告同时列出两个规模和跨规模宏平均，三个进化 seed 也分别报告。

- 改进百分点：`FACO gap − GP gap`，正数表示 GP 更好。
- 相对路线改善：`100 × (FACO cost − GP cost) / FACO cost`。
- 胜/平/负：对同一实例上的配对平均路线比较；明确以实例为单位。
- 95% 区间：10000 次分层配对 bootstrap，先重采样进化重复，再在各规模内重采样实例；固定统计 seed 91001。
- 显著性：先平均三个进化结果，再做两项整体配对 Wilcoxon 比较；对“原生 FACO、GPU FACO”这两项检验做 Holm 校正。两个规模的描述性结果单列，不追加未登记的主检验。

三个进化重复较少，报告完整区间和各次结果，不能只看一次最优成绩。任何失败或缺失成员都会阻止最终统计，不按效果筛掉失败任务。

## 5. individual 的输入、输出和成本

报告导出每个最终程序的表达式、树图、节点数、深度、实际引用的特征及完整 IR。在独立开发回放的第 1、100、500、1000、2500、5000 次决策保存实际 `12 × 32` 输入、32 个评分、合法动作掩码和选中动作。三个程序、两个规模、每规模两实例共 72 条决策记录。

记录发生在完整 5000 次轨迹上，不能通过重跑多个短预算冒充同一轨迹。GPU 仅在指定时刻复制小型决策数据，求解完成后一起传回 CPU；关闭采样时不分配这些缓冲，也不增加逐迭代 CPU 同步。

报告包含训练代际用时、实际 FE、测试摊销时间；准备、搜索和外部评分各自记账。CPU 原生 FACO 和 GPU 方法使用不同硬件，时间分别列出；同 GPU 上 GP 与无 GP 的差值才用于说明控制开销。

## 6. 自动运行、恢复和检查

从 GPLSACO 目录运行：

```bash
export TMPDIR="$PWD/.tmp"
export PIP_CACHE_DIR="$PWD/.cache/pip"
export CUDA_CACHE_PATH="$PWD/.cache/cuda"
.venv/bin/python scripts/run_campaign_v2.py --check-only
.venv/bin/python scripts/run_campaign_v2.py
```

默认目录为 `artifacts/v2/round-3seed`。协调器可在后台长期运行；同一命令接续已有目录，只允许一个协调器。它每 60 秒用 `gpu-free` 查找整个集群所有空闲 A5000，任务结束后重新发现设备并接下一项。没有空闲卡时等待，不消耗评价预算。每项任务在启动 CUDA 前再次核对 UUID、型号和空闲情况；其他用户抢先使用的卡会被放回等待队列。

一张卡同一时刻只接本项目一个任务。所有服务器的空闲 A5000 都可以使用，不卡死在 cuda07 或 cuda10。开发标定按控制器和实例/求解 seed 面板拆分，baseline、验证和测试也拆为面板任务。训练三个 seed 分别占卡并行，个体、实例/求解 seed、ants 在卡内展开；GPU 几何数据跨个体共享，个体状态独立。

本轮已在串行标定保存第 183 个完整任务后移交，已保存的 183 条面板轨迹直接复用；未保存的下一任务交给新队列，剩余 57 个任务分卡执行。标定继续使用同一 `build/v2-exact`、原来的 24 个控制器、实例、seeds 和检查点，不因分卡更改参数。原始大日志保留，只以文件位置引用，未重新评分已完成路线。接续声明位于 `calibration/manifest.json`，完整汇总在 `calibration/summary.json`；本轮 `frozen.json` 从该汇总选择 H。移交入口为 `scripts/import_campaign_calibration.py`，它要求原串行进程与旧协调器先退出。

完成结果、训练进度和评分按普通任务编号保存。重新运行协调器不会重复启动已完成任务；原远程进程仍存活或暂时失联时保留原任务，不能假定失败后在另一张卡重复运行。仅基础设施失败允许一次自动重试，数据或算法错误会保留现场并停止依赖步骤；已保存的 GPU 输出/外部评分直接复用。训练恢复允许更换 A5000，算法参数与数据声明保持相同。

正式启动要求 [campaign_verification.json](../../../results/v2/campaign_verification.json) 中构建与检查通过。检查包括 CUDA/C++ 与 Python 回归、两张 A5000 的完整轨迹直接比较，以及独立开发数据上的小规模完整流水线。工程轮次为 3 seed × 2 代 × 8 个体，训练 H=10、验证/测试=20；它只证明程序衔接可执行。

多主机扩展另见[并行检查记录](../../../results/v2/cluster_parallel_verification.json)：281 项 Python 测试通过；三 seed 跨主机同时派单、H 冻结前固定 baseline、已有曲线移交和缺失成员拒绝均有针对性检查。实际 GPU 上检查两规模完整曲线返回与恢复；原生 FACO 在 cuda07、cuda08、cuda10 上的两规模完整路线一致。
