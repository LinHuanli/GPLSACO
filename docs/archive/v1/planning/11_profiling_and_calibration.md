# 成本剖析与预算校准契约

本契约在用户补充前制定并已完成测量。用户随后要求主实验按evaluation次数终止，详见[次数主协议](12_evaluation_count_protocol.md)；本文件的秒数候选只作为旧时间入口的工程记录。

本阶段完成v4 §5.6的资源证据并为G4提供统一预算依据，不新增研究问题。只使用已登记development池；正式测试与迁移成绩保持未揭盲。训练/模型优劣仍由后续E1–E4检验。

## 计时层级

1. 协调端记录数据/标签读取、IR/任务形成、worker启动、原生调用、外部核验、日志/checkpoint与总墙钟。嵌套时间分列，不重复相加为总成本。
2. CPU准备分为廉价tour、候选/最近8邻居尺度、NN初始tour、初始2-opt与最终核验。记录实际工作与用于固定预算的冻结扣费，两者不能互相替代。
3. 原生诊断使用同一CUDA流的event区间记录H2D/初始化、十二特征与区域、GP评分、动作/重启、构造＋LS、归约、信息素、指纹和档案/反馈。主机组装、阻塞D2H调用、独立排列/成本核验另用单调时钟测量；H2D调用耗时与初始化event区间重叠，不重复相加。
4. 构造和LS共用内核，用仅在诊断模板启用的每block设备周期计数区分初始化、构造、LS和收尾。周期总和是block工作分布，不能把并发block周期和当成GPU墙钟；整kernel event时间才是其流水线区间。所有十二特征共享区域摘要，先报告完整特征内核成本，不假设共享工作能唯一分摊到单个终端。

profile固定批次、显式固定elapsed特征值，排除计时开销改变动作的反馈；使用相同程序/seed/坐标的未插桩固定批次对照，核查tour、工作计数、控制状态/动作和GP数值。再交替测量插桩与未插桩开销。profile结果只作成本诊断，不进入固定wall-clock的主fitness。原生产入口默认不创建CUDA events、不下载诊断数组，不启用设备周期计数。

## 预算依据

在统一32 colony×32 ants形状与单colony形状分别测量500/1K；不拿批量吞吐量换算单实例延迟。覆盖所有MNE等级与保持/重启、四种起始区域，包含统一开发程序与最大允许树大小的评分。生产路径的截止试验使用正常elapsed特征，不复用诊断中的固定值。

依据准备费用、完整提交批耗时分位数、实际超限和丢弃成本提出短/中/长预算；预先写清可接受的末批损失和搜索批数量，再冻结主预算。Static/Rule尚需在同一动作/档案/候选/LS接口中实现并充分配置；不能据某个开发GP表现挑预算，不能把8×3 smoke自动推广到正式128×50训练。

通用shape分配、事件/诊断缓冲、实际显存和离线总资源单列。保留失败、工具限制、冷/暖差异和插桩影响。每次重建前保存已验收二进制的内容摘要副本及对应Git源快照，避免后续构建覆盖历史复核所需的运行产物。

## 本次生产校准的预定覆盖与门槛

`configs/budget_calibration_v1.json`在生产测量启动前保存了由剖析p99和冻结准备费得到的候选值。短预算：32-colony覆盖全部32动作及两棵开发程序；单colony遍历同样16开发实例与四个MNE等级，均衡覆盖全部32动作各两次。中/长预算测两棵开发程序，单colony取预定第一实例，批量使用完整面板。所有条件均运行cached_charged与end_to_end，共424任务。中/长的两个程序不被称为覆盖所有动作轨迹。

按规模、colony数、准备模式分别判定：至少95%的短预算任务应完成20批搜索；至少99%的全部任务，其实际结束超出有效预算的比例应不超过5%。未达标任务保留并列出，不能删慢样本。超限比例不是整批丢弃时间；完整批次计数和丢弃计数另列。门槛通过仍只提供G4的开发成本证据，正式预算还须与Static/Rule及主池共享准备费一起冻结。
