# E2单因素动作限制与独立重训契约

2026-09-09。此阶段实现v4的2×2动作接口，沿用评价次数协议。M00的具体身份尚待完整776配置基线调优及独立验证结束；工程示例不参与其选择。正式M10/M01各5 seed、128×50及完整验证仍须单独冻结执行，不以工程8×3代替。

## 动作限制

动作编号为16b+4j+level，level对应MNE 2/4/8/16。先由共同底座建立区域、12特征与合法替代解mask，再施加因素限制，最后用原GP评分器在允许动作中求最大值，沿用原容差与最小ID决胜。

| 变体 | 原生行为 |
|---|---|
| M00 | 直接调用原Static/Rule入口，不执行评分树 |
| M10 | 同一M00规则决定是否请求重启；GP在该b下选择j/level |
| M01 | 同一M00规则决定j/level；GP在该组合下选择合法b |
| M11 | 直接调用原Full入口 |

固定的是规则函数及参数。停滞、epoch冷却均读取当前变体自己的已提交状态；不重放M00曾发生的动作序列，不将Rule简化为静态档位。所有决定在同一批开始前完成；重启后不重新计算一次档位。

M10的重启请求独立于M00的局部动作是否被外部mask屏蔽。若没有任何合法重启动作，退回允许的保持动作；跳过的请求不积压。M01/00的外部mask必须保留M00可能选择的全部保持动作。M11与M10只需保留至少一个保持动作。正式E2外部mask预期为UINT32_MAX，剩余限制完全来自两因素与共同的替代解可行性。

Static概率仍使用原Philox保留槽(batch, ant=UINT32_MAX, step=1)，不消耗蚂蚁或来源选择的随机流。所有条件保留完整重启事务、档案、区域生成、构造、LS、信息素和反馈更新。无墙钟截止，零FE保留共同初解，非整批限额拒绝。

## 接口、身份与恢复

原生evaluate_factorial_evaluations接收program与三字段FactorialPolicy：factorial_spec_id=1、variant、baseline_policy。即使M00不执行树，仍验证其IR/次数特征v2，避免错误入口被掩盖。原生返回规范factorial_policy。

FactorialTask在任务摘要中同时绑定IR、因素限制、完整M00规则和硬件协议；外部evaluator核对实际原生返回中的限制身份。FactorialTrainingRun仅接受M10/M01和Full终端集，分别从演化seed初始化，复用标准DEAP、完整精英/重复树重评与全部短名单验证。manifest绑定规则与专用训练代码；改变因素或M00配置不能恢复旧checkpoint。

代码位于隔离分支work/e2-factorial。main和E3的活动底座不变；既有状态分叉二进制也不覆盖。M00/M11复用既有端点的轨迹一致性是工程门槛；实际计时始终标注新二进制身份。

## 验收与正式依赖

CPU按32个动作逐项枚举合法组合，覆盖概率严格边界、停滞升级/饱和、周期和冷却、缺少alt以及外部mask。CUDA用独立CPU评分重算每批选择，比较M00/原基线、M11/原Full、同Engine A–B–A、单/批量、延迟和插桩，检查参考/档案/信息素与重启反馈事务。

真实开发面板和小规模独立重训用于检查32×32形状、500/1K距离、原返回持久化、全部FE、跨代选择与实际暂停恢复。正式TEST保持关闭。正式E2仍需冻结M00选择、10个单因素训练、M11五次训练的复用身份、四格TEST清单、实例内Syn和基础效应统计、行为摘要；不得把本接口称为RQ2完成证据。
