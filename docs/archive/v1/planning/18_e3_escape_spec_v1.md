# E3 Escape 开发契约 v1

本契约在Escape性能结果产生前登记，承接[实际图匹配v2](15_e3_graph_integration.md)。完整实现现已通过[工程验收](../reports/2026-09-09_escape_engine.md)，正式E3独立训练和统计仍待完成。求解以完整search-tour FE终止，默认没有墙钟截止。GP不能修改以下常量。

## 槽位与随机机会

构造每次选点使用独立随机域，以1/16概率建立一次替换视图。设该节点原行有m个有效槽位，则替换数量为floor(m/4)，再以(m mod 4)/4概率增加一个。位置与备用成员均无放回抽样；备用不足时只替换可用数量。右侧哨兵不变成新槽位，不按visited、距离、标签或适应度重新抽取视图。正常候选筛选在视图建立后执行。

替代节点的权重使用该真实节点距离和已有信息素查询规则：若其有主行信息素条目则读该条目，否则读colony当前default_trail。禁止继承被替换槽位的旧乘积。原ACO roulette/start/restart随机流保持原样；Escape随机域和计数分区随代码固定并单独测试。

随机流版本1使用现有colony的混合seed。Philox subsequence为`(uint64(batch)<<32) | domain | local_ant`；构造domain为`0x40000000`，LS为`0x80000000`，local_ant必须小于`2^30`。事件偏移为`uint64(event)<<32`个word，构造event为选点step，LS为节点ID。每事件最多使用保留的`2^32`个word，耗尽视为软件错误，不能进入相邻事件。1/16门控使用一个uint32的低4位；有余数时的随机取整使用下一uint32的低2位。位置和备用成员均用无模偏差拒绝采样与部分Fisher–Yates抽样。普通蚂蚁域和保留的`UINT32_MAX` colony域不被占用。

只有显式替换得到的槽位能申请新例外。普通主行、原备用回退和全局最近未访问回退只允许E0与本批已登记例外；所有来源耗尽则结束构造。

## 全部新增边的有限事务

每只蚂蚁预分配64条无向例外边，以小端点在先的形式去重。先消去移动前后相同边，再检查重定位全部3条或2-opt全部2条新增边。非E0且尚未登记的边必须同时取得许可与剩余容量，整组可容纳才允许候选移动。仅检查候选不写缓存；真正选中且接受移动时一次性提交整组。溢出拒绝整个移动、记录次数，不能部分登记或踢掉旧条目。

缓存只在当前蚂蚁当前构造与LS期间有效，每批开始重置；不同蚂蚁不共享，重复solve清空。父tour已有的图外边可原样保留，不能因此自动取得再次引入该边的许可。事务保存批次版本和预检长度，失效或缓存已变化的旧事务不能提交。

## 与扰动有关的 LS 视图

显式替换槽位引起的已接受非恒等重定位，把移动前的target、target_after、node、before、after五个端点登记为本蚂蚁的LS锚点，按节点去重；即使实际新增边均在E0，也登记实际扰动。恒等移动不登记。锚点在构造结束后固定，LS后续重激活不扩大例外许可范围。

每个锚点的LS行从相同备用表替换原有效槽位的期望1/4，使用上述随机取整规则；没有额外1/16门控。排除自身、原LS行成员和重复备用。构造后一次生成并按原坐标FP64距离、节点ID排序，同时携带逐槽替换标记，后续检查复用同一行。LS只在带替换标记的槽位申请整组新边，其余槽位仅使用E0与当前缓存。正常前缀提前break和每蚂蚁LS评价上限保持。不得追加第二遍等宽扫描。

参考元数据记录哪些节点实际使用了不同的LS视图，按节点ID索引。当前锚点与旧参考的视图足迹均进入pending初始集合；旧足迹保证失效例外恢复普通行时重新检查，但不授权新例外。足迹随迭代优胜tour、epoch、global、parent、档案选择和重启来源逐份传递，不能只用图外tour边推断。缓存本身不随参考传递。

足迹按“已建立且确有替换的视图”记录，即使本批LS评价限额未让该节点进入检查，也保留这个足迹。构造结束后按节点ID升序逐节点处理旧足迹、当前锚点，以去重追加方式进入已有pending；统计只计算当时新增的pending条目。LS行每批每蚂蚁只建立一次，不随后续重激活重新抽样。

## 容量、诊断与验收

正文物理主/备用/LS行宽16/64/20，小测试可按normalized_settings缩小。Escape实现拒绝超过这些上限的形状。按固定batch shape预分配例外缓存、逐蚂蚁锚点、LS行及逐槽标记，以及参考与档案足迹；Hard/Escape机制比较保留相同容量，另报实际使用量和Hard可省去的准备费用。普通无约束底座不承担这些缓冲。

Hard仅预留同样的例外工作容量，不在每次求解时清零它不会读取的缓冲。C++完整移动日志属于额外诊断容量，每蚂蚁最多`2n`项，生产Python不分配该日志；生产返回`escape_counters`跨colony/蚂蚁/批次汇总及预留字节数。图格式仍为1，Escape行为版本为1；随机比例、容量及来源不能由Python调用方或GP临时改写。

诊断需记录机会、替换槽数、接受的替换扰动、登记边数、容量拒绝、受影响及失效重激活节点数；C++完整轨迹携带缓存与足迹，生产返回汇总。验收覆盖完整移动边集oracle、未选择事务不污染、容量边界、失效、无替换时Hard一致、候选实际数量及真实距离顺序、父/epoch/档案足迹、重启、重复solve、零FE、CUDA内存/同步检查，以及匹配v2的真实开发面板。正式四条件仍须各自独立训练，不借用E1程序代替。
