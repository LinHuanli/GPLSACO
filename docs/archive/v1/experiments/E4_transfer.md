# E4：冻结规则的规模与结构迁移

状态：预注册草案；性能揭盲前冻结manifest必须存在。数据格式/距离/标签审计可先做，不能把审计与性能调参混为一谈。

## 1. 冻结包

保存每个evolution seed的验证选定IR、ERC位模式、grammar/feature/numeric版本、动作编码/mask、归一化、区域/档案、候选、LS限额、重启、源代码commit与依赖、Static/Rule/NoFeedback配置、训练/验证ID。包的hash写入E4 task manifest，任何变化是新的实验版本。

500/1K以外的解质量、行为轨迹不能决定本轮程序、阈值或候选默认值。10K评价次数限额按开发阶段预定义规模规则或独立底座工程校准确定，不根据GP在10K表现挑限额；实际运行时间另行报告。

## 2. 两条轴

规模轴：同生成分布的100、500、1K、10K；500/1K测试作域内参照，100检查回迁/饱和，10K是主要外推。各规模分组，不能混合样本加权冲淡10K失败。10K文件提供的标签是否精确最优单列证据，未证明时用reference gap术语。

结构轴：已恢复原始目标的TSPLIB逐实例，按规模与原距离类型分组；cluster/Gaussian只有经数据来源核对且未训练使用时才作未见分布补充。原TSPLIB距离不支持的实例列原因，不能偷偷用归一化连续坐标替代。

## 3. 运行与交付

所有冻结控制器使用相同目标设备/批形/预算；跨规模预算不同要明确。合成建议10 solve seeds，TSPLIB20；报告每个训练repeat的收益、全体平均和CI。外部求解器按距离支持及资源另列。

交付：规模性能图、10K质量—时间曲线、TSPLIB逐实例成本/gap/失败表、按距离/规模摘要、动作与实际新边分布、完整资源记录。检查是否所有任务源hash与冻结包相同，测试集未参与checkpoint选择，负gap/无标签/不支持实例都有处理。

1K有效但10K失败即表明当前规则外推不足；某距离类型失效即为适用边界。随后改动作集或在10K重训只能作为另立的后续版本，不回写本轮零样本结果。
